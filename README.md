# 云澜美术馆 · 团体参观调度台

面向美术馆运营/前台/讲解员的**团体参观预约、讲解设备借还与展厅分流**单页系统。
技术栈：**Vue 3 + TypeScript + Pinia + Vue Router + Vite**，纯前端、内置当日演示数据，无需后端即可完整体验全流程。

> 项目类型：前端。按约束不提供 Swagger/OpenAPI。

---

## 一、本地启动

### 方式 A：Docker 一键启动（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8080
```

停止：`docker compose down`

### 方式 B：Node 本地开发

要求 Node.js ≥ 20。

```bash
npm install        # 如遇 npm 缓存权限问题，可加：--cache /tmp/npm-cache
npm run dev        # 开发服务器，默认 http://localhost:5173
```

### 方式 C：本地构建并用静态服务器预览

```bash
npm run build      # 含 vue-tsc 类型检查 + vite 产物输出到 dist/
npm run preview    # http://localhost:4173
```

**本系统无登录页/账号体系**（工作人员内部调度台，演示数据已预置）。打开即为运营视角，无需测试账号。

## 二、页面结构

| 页面 | 路径 | 作用 |
| --- | --- | --- |
| 运营总览 | `/#/overview` | 馆内人数、耳麦库存/押金、待确认、投诉；6 个展厅实时客流（拥堵阈值/儿童/安静/无障碍/禁拍标记）；在馆与候场团队；讲解员排班 |
| 团体预约 | `/#/bookings` | 按状态筛选与搜索；新建预约；大团/儿童/无障碍/投诉/设备异常行内标记 |
| 新建团体预约 | `/#/bookings/new` | 采集团体类型、人数与**年龄层分布**、语言、无障碍、讲解主题、到馆时隙、联系人、车辆停靠位、是否借耳麦及数量 |
| 预约详情 | `/#/bookings/:id` | 全生命周期工作台 + 右侧**全流程时间线（投诉溯源）** |
| 展厅分流台 | `/#/dispatch` | 三安检通道负载、展厅分流图（★热门/📷禁拍/适合儿童/维护中）、临时闭展登记、受影响团队一键改道、分流原则 |
| 复盘与优化 | `/#/analytics` | 候场等待、讲解时长兑现率、满意度、设备异常率、分流热点、讲解员负荷，并自动生成大团规则/排班/限流优化建议 |

演示系统时钟固定为 **2026-10-01 10:42**（页面右上角），所有“实时”判断以该时刻为准。

## 三、推荐验证动线（对应题目每个场景）

预置 11 个团体，覆盖全部状态：

### 1. 工作人员确认预约（容量/热门展品/排班/安检/闭展）
- 打开 **B-2403 远山旅行社（56 人银发团，无障碍）**：系统自动推荐无障碍通道与可排讲解员，
  生成路线时**自动排除仅楼梯可达的陶瓷珍品阁 H6**；大团提示拆 2 批（30+26，间隔 15 分钟）。
- **B-2406 樱之会（日文团）**：讲解员下拉中只有陈牧（懂日文）可排，其余讲解员标注不可排原因。
- **B-2404 晨星幼儿园（幼儿 24 人）**：儿童占比 >50% 时提示安静展厅需分组轻声讲解。
- 可修改批次时间/通道，页面实时重算每个展厅预计客流与安检排队；阻断项未消除不能确认，也可驳回并记录原因。

### 2. 到馆核验、发耳麦、排批次
- **B-2402 华远科技（已到馆）**：在详情页完成实到成人/儿童核验、28 台耳麦发放（押金 ¥5,600）、
  查看通道 B 安排后点“安排入馆”。

### 3. 讲解途中异常（同一预约内联动调整）
- **B-2401 阳光小学（讲解中，已预置迟到 5 分钟、儿童走散、H1 拥堵分流的完整时间线）**：
  - “完成本厅 → 进入下一厅”推进路线；
  - **调整参观顺序/改路线**：拖动排序、跳过、加入备选厅（每个备选厅标注适合儿童/禁拍/维护/实时客流），
    应用后讲解时长重算，并**自动顺延同通道后续团队（B-2402）的入场时隙**；
  - **登记儿童走散**：后续展厅与下游批次顺延；
  - **讲解员临时替换**：按语言/主题/当班/时段校验可接替人选；
  - **耳麦损坏/遗失**：逐台登记，费用实时计入押金结算；
  - 在**展厅分流台**对任意展厅“登记临时维护/闭展”：相关团队时间线立即出现改道告警、计划展厅变“待改道”。

### 4. 离馆核对、押金、满意度
- 在详情页底部核对耳麦归还（可批量“复检正常”，也可逐台定损坏/遗失）、
  查看计划 vs 实际讲解时长、跳过厅数、候场等待分钟，打分后结算：
  押金 ¥200/台，损坏扣 ¥50/台，遗失赔 ¥300/台，自动计算应退金额。

### 5. 投诉与溯源
- **B-2407 博研教育（已离馆）**：预置“讲解缩水 + 等待过长”投诉。
  详情页右侧时间线完整呈现：到馆时间、安检等待、**讲解员变更（赵岚→陈牧）**、
  **路线压缩（H2→H1→H3 45 分钟 → H2→H1 30 分钟）**、各时点展厅容量快照（如 通道A 38/40）、
  耳麦损坏与押金结算。可填写处理结果归档。
- 也可对任意离馆团新登记投诉。

### 6. 优化复盘
- `/#/analytics` 查看等待/兑现率/满意度图表与自动建议，例如：
  早高峰通道 A 拆批、H1 书画厅团队时隙限流、志愿者连班保护、儿童团固化“互动厅→庭院”路线等。

### 安静观展与团队体验的平衡
展厅与路线卡片上始终可见三类标记：**适合儿童**（互动探索厅/雕塑庭院）、**📷 禁拍展品**
（《溪山行旅图》、浮世绘、当代影像墙等）、**维护中/临时闭展**；安静展厅的拥堵阈值为容量 70%（普通厅 85%），
调整路线时不可达/拥堵/维护中的展厅不会出现在备选里。

```

├─ types/            领域模型（预约/路线/设备/事件/展厅/讲解员…）
├─ data/seed.ts      展厅、展品、讲解员、闭展、11 个团体与历史时间线种子

├─ config.ts         容量阈值、批次、押金等运营常量

├─ components/       状态徽章、容量条、路线流、时间线、各阶段操作面板
└─ styles/main.css   美术馆风格设计系统（宣纸/墨色/朱砂）
```
